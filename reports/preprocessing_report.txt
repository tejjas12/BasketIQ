IMPORTANT TRANSACTION ASSUMPTION:
The source file has Member_number and Date but no invoice number.
Therefore, each unique Member_number + Date pair is treated as one basket.
This is a practical approximation and must be disclosed in the project report/viva.
It may combine multiple purchases by the same customer on the same day.

PREPROCESSING PERFORMED:
- Selected and validated the three required source columns.
- Converted Member_number to numeric and then integer.
- Parsed dates using the source format DD-MM-YYYY and standardized to YYYY-MM-DD.
- Trimmed whitespace and converted product descriptions to lowercase.
- Removed missing/invalid customer, date, or product rows.
- Removed exact duplicate customer-date-product records.
- Created TransactionID = Member_number_Date.
- Created transaction-product, basket-list, and one-hot basket representations.
- Generated customer and product frequency summaries.
